# seshat — 실행 계획

> **앞으로 할 일만 담는 문서다.** 끝난 것은 결과를 `MASTER.md` 로, 왜 그렇게 됐는지는
> `DECISIONS.md` 로 옮기고 **여기서는 행을 지운다.** 포인터도 남기지 않는다.
>
> | 문서 | 시제 | 담는 것 |
> |---|---|---|
> | **`docs/PLAN.md`** | **미래** | **남은 일 · 범위 밖 · 위험 (이 문서)** |
> | `docs/MASTER.md` | 현재 | 규약 · 계약 · 평가 · 기계 |
> | `docs/DECISIONS.md` | 과거 | 왜 그렇게 됐나 (append-only) |
>
> 서술 규약은 MASTER §0 이고 `tools/check_docs.py` 가 강제한다.

### 이 문서의 규약

| 규칙 | 강제자 |
|---|---|
| 남은 일은 **§1 표 하나**에만 산다 | `check_plan` 「표 행이 §1 밖에 있다」 |
| §1 제목이 행 수를 든다 — `## 1. 남은 일 — N행` | `check_plan` 「제목은 N행인데」 |
| **행 번호는 영구 식별자다.** 결번이 정상이고 지운 번호는 다시 쓰지 않는다. 당기지 않고 빈자리를 채우지 않는다 | `check_plan` 「오름차순 · 겹친다」 |
| 상태는 📄 🟡 ⏳ ⚠ 넷뿐이다. 닫힌 행은 지운다 | `check_plan` 「어휘 밖」 · 「닫힘 표시」 |

| 표기 | 뜻 |
|---|---|
| 📄 | 할 일이 정해졌으나 코드 · 실측으로 확인 안 됐다 |
| 🟡 | 미결정. 판단이 필요하다 |
| ⏳ | 대기 — **여기서 못 푼다.** 막고 있는 것이 행 안에 있다 |
| ⚠ | 전제가 틀리기 쉽다. 다른 표기와 함께 쓴다 |

## 0. 다음 한 수

**#1 평가셋을 세우고 #4 로 Nova Lite 를 잰다. 자부터 댄다.**

thoth 에서 가장 비싸게 배운 것이 "재지 않은 것을 고치면 고친 줄 모른다" 였다
(thoth DECISIONS §93 · §107). 모델을 하나도 내려받기 전에 **이길 대상의 점수**가 있어야 한다.

1. `data/eval/seed.jsonl` 12줄의 `ref` 를 사람이 검수한다 — 초안은 모델이 썼다
2. 도메인 문장을 100줄로 늘린다. 시험 문제를 옮기지 않고 **직접 쓴다**(DECISIONS §2)
3. thoth 배포본을 `evaluate --thoth` 로 잰다. 그 수가 첫 기준선이다

★ #2 는 #6 의 전건이지 #1 의 전건이 아니다. 평가는 쌍 로그 없이 선다.

## 3. 범위 밖

| 항목 | 사유 |
|---|---|
| 처음부터 학습(from scratch) | 데이터 · 연산 모두 사전학습 모델을 이길 수 없다 |
| 쌍 데이터 · 가중치의 저장소 커밋 | 원문이 사이트의 저작물이다. 저장소가 비공개여도 커밋하지 않는다 |
| 시험 문제를 평가셋에 옮기기 | 위와 같다 |
| 범용 번역 벤치마크 경쟁 | 목표는 좁은 과제에서 Nova Lite 를 넘는 것이다 |
| GPU 상시 기동 서빙 | 유휴에도 나간다 |
| thoth 계약을 이 저장소에서 바꾸기 | 계약은 쓰는 쪽이 정한다. 바꿀 일이 있으면 thoth 에서 바꾸고 복사해 온다 |

## 4. 위험

| 위험 | 영향 | 대응 |
|---|---|---|
| ⚠ Bedrock 출력의 학습 사용이 막혀 있다 | 쌍의 정답을 쓸 수 없다 | #2 를 #6 앞에 둔다 |
| ⚠ 평가셋이 작아 차이가 잡음이다 | 좋아진 줄 알고 나쁜 모델을 끼운다 | #1 을 100줄로. 차이가 작으면 끼우지 않는다 |
| 평가셋이 학습에 샌다 | 점수가 거짓말을 한다 | 평가 문장은 `.local` 출처로 나가 쌍에 남지 않는다(DECISIONS §3) |
| 6GB 에 안 들어간다 | 로컬 확인이 막힌다 | 학습은 원격, 로컬은 양자화 추론만 |
| 라이선스를 늦게 본다 | 튜닝한 모델을 못 쓴다 | 대장이 첫 호출부터 센다(DECISIONS §6) |
