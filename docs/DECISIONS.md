## §1. 번역기와 모델을 다른 저장소에 둔다

**2026-09-22**

### 결정

thoth 는 껍데기(확장 · 워커 · 배포 · 쌍 로그)로 닫고(thoth §110), 모델은 이 저장소에서
만든다.

- **의존성이 다르다.** thoth 워커의 Lambda 패키지는 18KB 이고 의존성이 0 이다. 모델
  쪽은 torch 계열이 들어온다. 한 저장소면 CI 와 커밋 훅이 그 무게를 진다
- **데이터가 다르다.** thoth 는 공개 저장소이고, 모델은 사이트 원문이 든 쌍을 먹는다.
  같은 작업 트리에 두면 언젠가 섞여 올라간다
- **수명이 다르다.** 모델은 실험하고 버리는 것이 일이고, 번역기는 안정적이어야 한다

둘을 잇는 것은 thoth 의 `ENGINE=http` 계약 하나다(thoth §109).

**문서 규약은 그대로 옮겼다.** 3축(PLAN · MASTER · DECISIONS), 3인칭 평어체, 해결된 행
삭제, 번호 재사용 금지. `tools/check_docs.py` 를 복사해 대상 디렉터리만 바꿨다.

강제자 — `tools/check_docs.py` · `tools/doc_fsck.py` — 규약이 thoth 와 같은지는 사본 머리의 출처가 말한다

### 배운 것

**나누는 이유는 코드가 아니라 데이터와 의존성이다.** 코드 크기로는 한 저장소로 충분했다.
갈라야 하는 것은 공개 범위가 다른 데이터와, 무게가 다른 의존성이었다.

## §2. 데이터는 저장소에 들이지 않는다

**2026-09-22**

### 결정

쌍 로그 · 학습 데이터 · 가중치 · 실행 결과를 커밋하지 않는다. `.gitignore` 가
`data/private/` · `runs/` · `models/` · `*.parquet` · `*.safetensors` 등을 막는다.

평가셋도 같다. **시험 문제를 옮기지 않고 이 저장소가 직접 문장을 쓴다.** 0판 12줄은
AWS 데이터 엔지니어링 문장을 새로 썼고 CC0 로 둔다. 정답 초안은 모델이 썼으므로 사람
검수 전이라고 머리줄에 적었다.

강제자 — `.gitignore` · `tests/test_eval_set.py::test_머리줄이_출처와_라이선스를_적는다`

### 배운 것

**thoth 가 처음부터 지킨 선을 그대로 긋는다.** thoth 는 "원문을 공급하는 것은 저장소가
아니라 사용자 브라우저" 라는 구조로 저작권 문제를 비켜 갔다. 모델 저장소는 원문을 직접
만지는 첫 자리이므로 그 선이 가장 쉽게 무너지는 곳이다.

## §3. 계약은 thoth 가 정하고 기준선은 thoth 가 준다

**2026-09-22**

### 결정

- **계약 검사는 thoth 의 것을 복사한다.** `tests/thoth_conformance.py` 는 thoth
  `tools/engine_conformance.py` 의 사본이고 여기서 고치지 않는다. 쓰는 쪽이 계약을
  정하고 만드는 쪽이 지킨다
- **Nova Lite 기준선은 thoth 워커를 그대로 부른다.** 워커의 `/translate` 도 같은 응답
  모양이므로 `evaluate` 가 두 서버를 똑같이 잰다. Bedrock 호출 코드를 이 저장소에 다시
  쓰지 않는다
- **평가 문장은 쌍에 남지 않는다.** 워커를 잴 때 `source.site` 를 `eval.seshat.local` 로
  싣는다. thoth 는 `.local` 사이트를 쌍으로 남기지 않는다(thoth §104). 평가셋으로
  학습하면 평가가 거짓말을 한다

강제자 — `tests/test_serve.py::test_thoth_적합성_검사를_통과한다` · `tests/test_evaluate.py::test_thoth_워커를_잴_때는_평가_출처를_싣는다`

### 배운 것

**같은 계산을 두 곳에 두면 언젠가 갈린다**(thoth §14). 기준선을 재려고 Bedrock 을 다시
부르면 프롬프트 · 후처리 · 배치가 배포본과 달라지고, 그 기준선은 배포본의 점수가 아니게
된다. 배포본을 그대로 부르는 것이 가장 정직한 기준선이다.

## §4. 기본 의존성은 0 이다

**2026-09-22**

### 결정

서버 · 평가 · 계약 검사는 표준 라이브러리로 선다. chrF++ 는 `eval` 그룹(sacrebleu)이고,
신경망 지표와 학습은 그 뒤에 따로 그룹을 둔다. 백엔드는 무거운 import 를 함수 안에서
한다.

**서버도 표준 라이브러리다.** 계약이 JSON 두 개라 프레임워크가 얹을 것이 없고, 모델
추론이 병목인 서버에서 HTTP 층은 재기 전까지 문제가 아니다.

강제자 없음 — 설계 판단이다. `pyproject.toml` 의 `dependencies = []` 가 그 상태를 적고, 어기면 CI 의 `uv sync` 가 무거워질 뿐 실패하지 않는다

### 배운 것

**의존성을 최대한 쓰는 것과 모든 자리에 의존성을 들이는 것은 다르다.** 모델 · 학습 ·
양자화는 세계 최고 수준의 도구를 그대로 쓴다. 그러나 계약 검사가 torch 를 받으면 CI 가
몇 분씩 느려지고, 그 비용은 얻는 것이 없다. thoth 의 Lambda 가 18KB 인 이유와 같다.

## §5. 문서 강제자를 thoth 에서 사본으로 가져온다

**2026-09-22**

### 결정

`tools/check_docs.py` · `tools/doc_fsck.py` · `tests/test_doc_enforcers.py` 는 thoth 의 사본이다
(thoth DECISIONS §111). 파이어레인 · 하토르의 규약을 thoth 가 먼저 옮겼고, 이 저장소는 첫 커밋부터
같은 규약 아래 선다 — PLAN §1 표 하나 · 영구 번호 · 닫힌 상태 어휘 · 참조 실재 · 강제자 줄 ·
문서가 가리키는 실물 · 카나리아.

- **사본 머리에 출처를 적는다.** 이 저장소에 맞춘 차이는 `# seshat:` 표시 줄뿐이다 — 저장소 이름 ·
  참조를 찾을 디렉터리 · 강제자 줄을 요구하기 시작하는 절
- **강제자 줄은 §1 부터 요구한다.** thoth 는 옛 절에 소급하지 않으려고 §108 부터 걸었지만 이
  저장소는 처음부터 건다. §1–§4 는 공개 전에 강제자 줄을 채웠다 — 아직 아무도 읽지 않은 기록이다
- **사본은 참조 검사에서 뺀다.** 사본은 원본 저장소의 절을 가리키고, 고치면 원본과 갈린다
- thoth 의 적합성 검사(`tests/thoth_conformance.py`)도 같은 방식이다(§3)

강제자 — `tests/test_doc_enforcers.py` · `tools/check_docs.py` · `tools/doc_fsck.py`

### 배운 것

**규약을 옮길 때 강제자를 같이 옮긴다.** thoth 는 규약만 있고 강제자가 없는 동안 PLAN 표가 다섯
절에 흩어졌다(thoth DECISIONS §111). 새 저장소는 늙을 문서가 아직 없을 때가 강제자를 걸기 가장
싼 때다.

## §6. 모델 가중치 라이선스 대장

**2026-09-22**

### 결정

`seshat/licenses.py` 가 대장이고 `tools/check_model_licenses.py` 가 코드와 대조한다.

- 가중치를 받는 호출(`from_pretrained` · `snapshot_download` · `hf_hub_download` · `Translator`)의
  첫 문자열 인자가 대장에 없으면 실패한다
- 대장에 올리려면 라이선스 · 상업 가부(`yes` · `no` · `unknown`) · 확인한 곳과 날을 적는다.
  **모르면 `unknown`** 이다 — 코드 라이선스를 가중치에 넘겨 적지 않는다
- **비상업을 막지 않고 센다.** 비교 실험에서 비상업 모델을 재는 것은 정당하다. 서빙 백엔드
  (`seshat/backends.py` · `seshat/serve.py`)가 `yes` 아닌 가중치를 부를 때만 실패한다

하토르가 먼저 겪었다 — 검색과 화성 판정이 비상업 가중치 위에 서 있었고 백칠십 건의 결정 동안
아무도 보지 않았다(하토르 D-0217). 튜닝을 마친 뒤에 알면 처음부터 다시 한다.

강제자 — `tools/check_model_licenses.py` · `tests/test_model_licenses.py`

### 배운 것

**라이선스는 첫 호출에서 보는 것이 가장 싸다.** 모델이 아직 하나도 없을 때 대장을 비워 두고
검사를 걸면, 첫 가중치가 들어오는 커밋이 곧 라이선스를 적는 커밋이 된다.

## §7. thoth 의 쌍 집계를 넘겨받는다

**2026-09-22**

### 결정

thoth 는 껍데기로 닫혔다(thoth DECISIONS §113). 거기서 지운 행 둘 — 캐시 히트율 · 문자량 ·
엔진별 비용의 Athena 집계와 빈출 미등재 용어 후보 — 을 PLAN #11 로 받는다. 쌍을 읽는 것은
모델 쪽의 일이다.

- 미등재 용어 후보는 자동 반영하지 않는다. 사람이 승인해 thoth 용어집에 올린다(thoth 의 규약)
- 집계 결과는 `data/private/` 에 두고 커밋하지 않는다(§2)

강제자 없음 — 계획의 인수다. 행은 `tools/check_docs.py::check_plan` 이 본다

### 배운 것

**저장소를 닫을 때 넘길 일은 받는 쪽에 행으로 세운다.** 보내는 쪽에서 지우기만 하면 일이 공중에
뜬다.

---

## §8. 저장소는 비공개다

**2026-09-22**

### 결정

thoth 는 공개이고 이 저장소는 비공개다. 학습 데이터 · 가중치 · 실험 결과를 다루므로 실수의 반경을
줄인다. **그래도 데이터는 커밋하지 않는다**(§2) — 비공개는 두 번째 방어선이지 첫 번째가 아니다.

thoth 의 README 는 이 저장소를 링크하지 않고 이름만 적는다. 비공개 저장소의 링크는 남에게 404 다.

강제자 — `.gitignore` · `.github/workflows/ci.yml` 의 gitleaks

### 배운 것

**공개 범위는 규칙의 대체가 아니다.** 비공개라서 커밋해도 된다고 읽는 순간 저장소를 공개로 바꾸는
날 한꺼번에 샌다.

## §9. 후보를 폴링했고, 가장 센 후보는 쓸 수 없었다

**2026-09-22**

### 증상

thoth 통합 기획서 2.0 을 쓰면서(thoth DECISIONS §116) PLAN #5 의 후보 표를 처음으로 다시 폴링했다.
표는 2026-05 기준이었다. 새로 보인 것이 둘이다.

- **TranslateGemma**(Google, 2026-01) — Gemma 3 기반 번역 전용 · 55개 언어 · 4B 가 있다
- **HY-MT1.5**(Tencent, 2025-12, 1.8B · 7B)와 **Hunyuan-MT-7B**(WMT25 에서 31개 부문 중 30개 1위를
  발표) — 공개 번역 모델 중 지표가 가장 강하고 용어 개입을 지원한다

그리고 `data/eval/README.md` 가 "저장소는 공개이고" 라고 적고 있었다. 이 저장소는 비공개다(§8).

### 원인

HY-MT 계열의 라이선스(Tencent HY Community License)는 사용 허락 지역(Territory)을 "EU · 영국 ·
대한민국을 뺀 전 세계" 로 정의하고, 지역 밖의 사용 · 복제 · 수정을 허락 밖으로 둔다. **비상업
조항과 다르다** — 비상업은 비교 실험에 쓸 수 있지만, 지역 밖이면 비교도 허락이 없다. 대장(§6)은
상업 가부만 셌고 이 종류를 가를 어휘가 없었다.

README 문구는 저장소를 비공개로 정하기(§8) 전에 쓴 것이다.

### 결정

- `seshat/licenses.py` 에 `EXCLUDED`(접두사 → 사유)를 둔다. 코드가 어디서든 부르면 실패, 대장에
  올려도 실패다
- PLAN #5 후보 표에 TranslateGemma 를 올리고 HY-MT 를 "쓰지 않는다" 로 적는다
- README 문구를 고쳤다 — 비공개여도 커밋하지 않는다

강제자 — `tools/check_model_licenses.py::check` 「쓸 수 없는 가중치」 · `tests/test_model_licenses.py::test_쓸_수_없는_가중치는_비교에서도_걸린다`

### 배운 것

**라이선스의 축은 상업 가부 하나가 아니다.** 누가 · 어디서 쓰는가도 조건이다. 대장의 어휘가 하나뿐이면
그 밖의 조건은 "yes" 나 "no" 로 뭉개진다 — 지역 제외를 "no" 로 적었다면 비교 실험에서 조용히
불렸다.

**가장 센 후보가 먼저 걸러진다.** 지표 순으로 후보를 고르고 라이선스를 나중에 봤다면 여기서 첫
주를 버렸다. 라이선스를 모델보다 먼저 보는 이유의 실례다.

## §10. 강제자 사본을 다시 받는다 — 파일 끝 검사

**2026-09-22**

### 결정

thoth 가 `check_docs.py` 에 파일 끝 검사를 더했다(thoth DECISIONS §118). §9 를 덧붙이면서 이 저장소의

강제자 — `tools/check_docs.py::check_eof` · `tests/test_doc_enforcers.py::test_파일_끝은_줄바꿈_하나다`

### 배운 것

**사본은 원본의 검사를 따라 받는다.** 원본에서 규칙이 늘면 사본이 있는 곳마다 같은 날 받는다.

## §11. 목표는 영→한 범용에서 AWS Translate 를 넘는 것이다

**2026-09-22**

### 증상

thoth 통합 기획서와 이 저장소의 PLAN 이 목표를 "좁은 과제(AWS 자격증 문항 · 합쇼체)에서 Nova Lite 를
넘는 것" 으로 적고 있었다. PLAN §3 은 "범용 번역 벤치마크 경쟁" 을 범위 밖에 두었다. 다음 한 수는
"평가셋 12줄을 사람이 검수한다" 였다. 사용자가 둘 다 틀렸다고 했다 — AWS Translate 를 못 이길
거면 이 저장소를 시작할 이유가 없고, 평가셋 정답을 사람이 채점하는 일은 청사진이 아니다.

### 원인

- **장비를 목표의 천장으로 읽었다.** GTX 1660 Ti 가 지금의 천장인 것은 맞지만, 사용자는 연말에
  학습용 데스크탑(예산 500만 원)을 들이고 1년짜리 장기 프로젝트로 본다. 지금의 장비로 1년의 목표를 깎았다
- **상대를 과대평가했다.** AWS Translate 는 2017년에 나온 범용 NMT 다. WMT25 영→한 예비 순위(Kocmi 외,
  arXiv 2508.14909)에서 7B 공개 모델 Shy-hunyuan-MT 가 1위였고 Gemini 2.5 Pro · GPT-4.1 이 그 뒤,
  익명 상용 시스템(ONLINE-B)은 7위권이었다. 작은 공개 모델이 상용 번역을 넘는 판이다
- **첫 단계를 목표로 말했다.** 자를 먼저 대는 순서는 맞지만 자는 청사진의 부품이다

### 결정

- **목표 — 영→한 범용에서 AWS Translate 를 넘는다. 1년.** 판정은 FLORES+ devtest(CC BY-SA 4.0)와 도메인셋
  위의 숫자로 한다. thoth 의 도메인은 그 위의 특화다
- **AWS Translate 를 직접 잰다** — `backends.aws_translate` · `evaluate --backend`. 서빙하지 않는
  기준선이라 `BASELINE_ONLY` 에 두고 용어집을 싣지 않는다. §3 의 "Bedrock 을 다시 부르지 않는다" 는 그대로다
  — Nova Lite 는 제품 모드의 기준선이고 계속 thoth 워커로 잰다
- **정답은 사람이 쓰지 않는다.** 교사 여럿의 합의 + thoth 검사기 + QE 로 만들고 어긋나는 줄만 드러낸다
- **장비가 단계를 정한다** — ① 지금(학습 없이: 기준선 · 논문 대장 · N-best + QE · 용어 자리표시 · RAG ·
  모델 병합) ② 연말 전(원격 T4 · 스팟: Apache 교사 증류 · LoRA · 작은 강화학습) ③ 새 장비(GRPO — 보상은
  thoth 검사기 + QE, 보상마다 반대 추 · 학생 구조 대결)
- **용어가 가장 큰 과제다.** 첫 답은 구조다 — 서비스명을 자리표시로 바꿔 번역하고 되돌린다(PLAN #15)
- **남이 한 학습은 논문으로 파싱한다**(PLAN #13). HY-MT 는 가중치를 못 쓰지만 방법은 읽는다
- 범위 밖에서 "범용 번역 벤치마크 경쟁" 을 지웠다. "처음부터 학습" 은 큰 모델에만 두고 작은 학생(#20)은 예외로 했다

## §12. 이 저장소는 연구다 — 가설 대장을 실험의 문으로 둔다

**2026-09-22**

### 증상

§11 을 세운 직후의 다음 한 수가 "AWS Translate 를 FLORES+ 로 잰다" 였다. 사용자가 막았다 — 인프라도

제품이고 seshat 은 엔진 — 뇌 — 이다.

### 원인

thoth 에서 배운 "재지 않은 것은 고치지 않는다" 를 "먼저 잰다" 로 옮겼다. 제품에서는 맞는 순서였다 —
고칠 것이 이미 있었다. 연구에서는 무엇을 확인하려는지(가설)가 먼저고, 측정은 그 가설의 도구다.

- **가설 대장** `docs/hypotheses.md` — 한 줄에 직관 · 트랙 · 검증 방법 · 비용 상한 · 근거. 상태는 제안 ·

  문형 커리큘럼 · 탐침 · 강화학습 보상 · 평가 EDA
- **에이전트와 그래프는 오프라인 교사 공장이다.** 실시간 번역을 여러 번 호출로 돌리면 속도 · 비용 목표가
  깨진다. 에이전트가 만든 최고 품질 데이터를 단일 모델에 증류한다
- **문형 템플릿(5형식 × 어휘)은 번역 방식이 아니라 탐침 · 커리큘럼 · 증강이다.** 예제 기반 번역은 신경망
  번역에 졌지만, 통제 문장은 약한 구문을 찌르는 데 가장 싸다
- PLAN #12(AWS Translate 기준선)를 ⏳ 로 — 가설이 부를 때만, 첫 호출은 H-002 의 300문장. 행 22–25

- 앞단은 없다 — 화면은 thoth 다. 경계는 HTTP JSON 이고 서버 대 서버다(MASTER §8)
- README 의 "좁은 과제" 방향을 §11 · §12 로 고쳤다

강제자 — `tools/check_hypotheses.py::check` · `tests/test_hypotheses.py::test_규칙마다_걸린다` · CI 의 가설 대장 검사

### 배운 것

**제품의 순서를 연구에 옮기지 않는다.** 제품은 고칠 것이 먼저 있고 재서 고친다. 연구는 물음이 먼저 있고
재서 답한다. 물음 없이 잰 숫자는 답이 아니다.

## §15. H-001 — 자리표시는 누설을 줄였지만 0 으로 만들지 못했다

GPU 러너(GTX 1660 Ti · WSL2)에서 `gpu-eval.yml` 첫 실행. 탐침 200줄(문형 14 × 온톨로지 어휘, seed 7 ·

## §16. 잃은 9% 는 관계절 하나에 몰려 있었고, 모델은 자리표시의 모양을 바꿨다

**2026-09-22**

### 증상

`tools/compare_runs.py` 로 H-001 두 결과를 줄 단위로 대조했다. 처치군이 이긴 줄 56 · 진 줄 13. **처치군의 손실은
거의 전부 관계절(`relative`) 문형에 있었다** — 이름 28 중 4 만 남았다(0.14). 나머지 열세 문형은 수동태 0.93 을
빼고 전부 1.00 이다. 진 줄의 출력은 이렇다.

```
원문  The role that S3 Glacier Flexible Retrieval writes to Amazon Athena must be encrypted.
처치  \[T1]이 \[T2]에게 보내는 데이터는 암호화되어야 합니다.
```

그리고 대조 도구는 "처치군에 자리표시가 남은 줄 0" 이라고 했다.

### 원인

- **모델이 자리표시의 모양을 바꿨다.** `⟦T1⟧` 을 마크다운처럼 이스케이프한 `\[T1]` 로 돌려줬다. `unmask` 는 `⟦T1⟧`
  만 받았으므로 그 자리를 되돌리지 못했다. 이름을 잃은 것이 아니라 **되돌리기가 못 알아본 것**이다
- **대조 도구가 같은 자리에 눈이 멀었다.** 남은 자리표시를 `⟦` 로만 셌다 — 바뀐 모양 26 개를 0 으로 셌다. 처음
  보는 실패를 셀 때 아는 모양만 세면 0 이 나온다(thoth DECISIONS §43)
- 관계절에서만 난 이유는 재지 않았다. 두 팔 모두 관계절의 머리 명사(`The role that …` 의 `role`)를 버리고 문장을
  다시 짰다 — 모델이 문장을 크게 고쳐 쓸 때 자리표시도 고쳐 쓴 것으로 본다. H-012(관형절)의 재료다

### 결정

- `terms.unmask` 가 바뀐 모양을 받는다 — `⟦T1⟧` · `[T1]` · `\[T1]` · `\[T1\]` · `【T1】`. 대조 도구의 남은 자리표시
  검사도 같은 모양을 본다. 두 정규식이 같은지 테스트가 대조한다
- `tools/rescore.py` — 결과 파일의 출력을 지금의 되돌리기로 다시 채점한다. **모델을 다시 부르지 않는다.** 가설의

## §30. 패치가 선 자리를 들고 온다 · 밀린 것은 번호 순서로

**2026-09-23**

### 결정

- 의존성 봇의 PR 을 GitHub 에서 합치자 원격 main 이 움직였고, 그것을 모르는 사본에서 만든 패치가

- 패치가 **기준 나무**(`Seshat-Base-Tree`)를 머리에 들고 온다. `tools/make_patch.sh` 가 넣고 `apply_patch.sh` 가

  커밋 해시가 아니라 나무 해시다 — 같은 내용을 다른 기계에서 커밋하면 해시는 달라도 나무는 같다

  밀린 것이 둘이면 뒤엣것부터 붙이려다 실패했다(2026-09-23 · 027 을 건너뛰고 028 을 먼저 시도했다)
- 봇이 합쳐지면 이쪽 사본도 그 커밋을 받아야 한다. 받지 않으면 이 검사가 매번 운다 — 검사가 우는 것이 조용히
  어긋나는 것보다 낫다

강제자 — `tests/test_sweep.py::test_상태를_명령줄로도_묻는다` · `tests/test_sweep.py::test_붙음_안_붙음_판정_못함`

### 배운 것

**어긋남은 붙이는 쪽이 아니라 만든 쪽이 안다.** 붙이는 기계는 "안 붙는다"까지만 말할 수 있다. 무엇을 기준으로
만들었는지는 만든 쪽만 알고, 그래서 그 사실을 **산출물에 실어 보내야** 한다.

## §31. H-022 기각 — 깨진 문체는 한 틀이다 · 종결 정규화

**2026-09-23**

### 결정

## §34. 온톨로지 2판 — 공식 표기를 문서와 대조한다

**2026-09-23**

### 결정

- AWS 한국어 문서와 대조해 개념 18 개의 공식 표기를 확정했다. **일곱 개가 틀려 있었다.**

  | 개념 | 1판 | 2판(공식) | 근거 |
  |---|---|---|---|
  | producer | 프로듀서 | **생산자** | streams/key-concepts |
  | consumer | 컨슈머 | **소비자** | streams/key-concepts |
  | consumer application | 컨슈머 애플리케이션 | **소비자 애플리케이션** | streams/key-concepts |
  | topic | 토픽 | **주제** | sns/sns-create-topic |
  | visibility timeout | 표시 제한 시간 | **가시성 제한 시간** | sqs/sqs-visibility-timeout |
  | lifecycle policy | 수명 주기 정책 | **수명 주기 구성** | s3/object-lifecycle-mgmt |
  | cross-account | 교차 계정 | **크로스 계정** | iam/access_policies |

  `term_off` 만 깎인다. 지우면 옳은 번역을 틀렸다고 센다
- 노드가 `ko_ref` 로 근거를 든다 — `<서비스>/<페이지>`. **URL 은 적지 않는다.** 깨지고, 서비스와 페이지
  이름이면 다시 찾는다(파이어레인 sources.yaml 의 규칙)
- `check_ontology --list` 가 대조 진척(18/60)을 찍는다. 2판은 한 번에 끝나지 않는다 — 남은 42 는 같은 방식으로
  채운다
- **문서를 저장소에 넣지 않는다.** 대조의 산출물은 표기와 그 자리뿐이다(카탈로그의 `aws-docs` 는 여전히 라이선스
  미확인이라 학습에 못 쓴다 · §22)

**모르는 것과 틀린 것은 다르다.** 1판은 「대조하지 않았다」 고 적어 두었고, 실제로 대조하니 18 중 7 이 틀렸다.

## §36. 서빙은 유휴 0 · 모델 크기는 서빙이 정한다

**2026-09-23**

### 결정

- 서빙 자리를 **유휴 비용 0** 으로 못 박는다 — Lambda 컨테이너(CPU · CTranslate2 int8)가 1순위, 서버리스 GPU 가
  2순위다. 상시 GPU · 관리형 엔드포인트 · 집의 장비는 쓰지 않는다(MASTER §13)
- 그래서 **끼울 모델의 크기와 속도가 먼저 정해진다** — int8 3GB 이하 · CPU 문장당 1초 이하. 4B 는 이 조건을
  못 넘는다. 4B 는 **교사**이고 서빙 대상이 아니다(PLAN #18 → #20 → #27 이 한 줄이다)
- 연말 장비는 **서빙 장비가 아니라 공장**이다. 학생을 만들 때까지 쓰고, 그 뒤에는 Lambda 가 일한다
- 무료로 얻는 것은 **저장**(HuggingFace Hub)과 **계산**(캐글 · 코랩 · GitHub Actions)이다. **상시 응답은 무료가
  없다.** 캐글 · 코랩을 서빙에 쓰지 않는다 — 상시가 아니고 약관 밖이다
- AWS Translate 백엔드가 리전 없이 호출되면 botocore 가 `NoRegionError` 를 던지는데, 그 말은 무엇을 적어야
  하는지 알려주지 않는다. 부르기 전에 보고 `.env` 의 `AWS_REGION` 을 말한다. **의존성을 들이기 전에 본다** —
  설정이 틀린 것을 설치로 덮지 않는다

강제자 — `tests/test_baselines.py::test_리전이_없으면_먼저_멈춘다` · `tools/check_docs.py`(MASTER §13)

### 배운 것

**배포 제약이 모델 설계를 정한다.** 어떤 모델을 만들지 먼저 정하고 나중에 띄울 자리를 찾으면, 띄울 수 없는
모델이 나온다. 유휴 0 이라는 한 줄에서 크기 · 속도 · 증류 · 학생 구조가 전부 따라 나왔다.

## §42. 자리표시 형식은 엔진마다 다르다

## §48. 범용 지시 모델은 배선이 다르다

**2026-09-23**

### 결정

- Qwen3 4B 를 TranslateGemma 의 배선(`/api/generate` · 같은 지시문 · `think: false`)으로 불렀더니 **영어 사고문을

- 범용 후보는 **채팅 API**(`/api/chat`)로 부른다. 체계 지시를 따로 싣고(`GENERIC_SYSTEM` — 번역문만 · 설명 금지 ·

- 그래서 H-032 의 비교는 두 층이다 — 범용 후보끼리(같은 배선)가 1층, 번역 전용(TranslateGemma)과의 비교가 2층이고

**0 점이 두 번 나오면 두 번 다 도구를 먼저 본다.** keep 0.000 은 자리표시 형식이었고(§42) term 0.000 은 배선이었다.

## §60. 처치가 일했는지를 결과가 말해야 한다

- 판은 둘이다 — 원문 · 온도 0, 그래도 안 되면 원문 · 온도 0.4. 첫 판이 온도 0 이라 **되풀이할 수 있다**

**지표가 안 움직였을 때 물어야 할 첫 질문은 「처치가 일어나긴 했는가」 다.** 그것을 못 세는 처치는 다음
실험에서도 같은 자리에 선다. 처치를 만들 때 **그 처치가 몇 번 일했는지를 세는 자리**를 같이 만든다 —
지표 옆이 아니라 처치 옆이다.

아니라 어디서 고칠지**로 안전해진다.

  **term_off 132/156(0.846) → 171/198(0.864)** · term_bad 0.000 · keep 0.993. 채택한다
- 늘어난 42 자리는 `encryption` 2 → 16 · `ingestion` 1 → 15 · `throttling` 4 → 18 이고, **그중 39 를
  모델이 이미 맞히고 있었다.** 분모가 늘었는데 비율이 올랐다 — 안 보이던 실력이 드러난 것이다
- **분모를 결과 파일이 든다**(`term_n`). 2026-09-25 에 `0.846` 을 보고 분모를 78 이라 읽었다(약분한
  `11/13` 에서 짐작했다). 실제는 `132/156` 이었고, 그래서 **「분모가 줄었다」 는 반대 결론**을 냈다
- 비율만 있는 지표는 두 숫자가 **같은 것을 재는지조차** 말해 주지 못한다. 사전이 넓어지면 분모가 움직인다

강제자 — `tests/test_evaluate.py::test_분모를_결과가_든다`

### 배운 것

**약분한 비율에서 분모를 짐작하지 않는다.** `0.846` 은 11/13 이면서 132/156 이고 66/78 이다. 세는 것이
움직이는 지표라면 **센 개수를 함께 싣는다** — 비율은 결론이고 개수는 증거다. §60 과 같은 규칙이 지표 쪽에도
선다 : 처치는 몇 번 일했는지, 지표는 몇 개를 셌는지.

- `read_rows` 가 둘 다 읽는다. 못 찾으면 **받은 파일 이름을 전부 보인다** — 형식이 또 바뀌면 그 줄이 말한다

하나가 막혀 있을 때 나머지 둘이 성한지는 아무도 확인해 주지 않는다.

## §72. 없는 것은 어떻게 얻는지 말한다 — 그리고 제안 가설을 일러 준다

**2026-09-25**

### 결정

- 없는 평가셋이 40 줄 역추적(`FileNotFoundError`)으로 나왔다. **카탈로그가 그것을 어떻게 얻는지 이미
  들고 있었다**(`data/catalog.toml` 의 `how`) — 아무도 묻지 않았을 뿐이다

  「이것을 돌리십시오」 라고 보낸 패치가 그 가설을 제안으로 두고 있었다. 문(§door)이 네 번 다 막았지만
  **막히는 것과 알려 주는 것은 다르다** — 막히면 사람이 한 번 더 왕복한다
- 실패가 아니라 물음이다. 진짜 제안일 수도 있으므로 패치는 그대로 만들어지고 경고만 선다

강제자 — `tests/test_eval_set.py::test_없는_평가셋은_받는_법을_말한다`

### 배운 것

**같은 실수를 네 번 하면 그것은 기억의 문제가 아니다.** 「다음부터 조심한다」 를 세 번 적고 네 번째를
틀렸다. 사람이 지키는 규칙은 사람이 바쁠 때 깨진다 — 규칙을 세 번 어겼으면 **그 규칙을 지키는 도구를
만드는 것이 그다음 일**이고, 그 도구는 대개 열 줄이면 된다.

## §73. `.env` 의 같은 열쇠 — 나중 줄이 이기고, 그 사실을 말한다

**2026-09-25**

### 결정

- FLORES+ 가 동의를 누른 뒤에도 401 이었다. 까닭은 권한이 아니라 **`.env` 에 `HF_TOKEN` 이 두 줄**
  있었기 때문이다 — 채팅에 붙였다 폐기한 토큰이 첫 줄에 남아 있었고 새 토큰은 `>>` 로 뒤에 붙었다
- **두 로더가 반대로 읽고 있었다.** 셸 로더(`tools/lib/env.sh`)는 소싱이라 나중 줄이 이기고, 파이썬
  로더(`seshat/paths.py`)는 `key not in os.environ` 이라 앞줄이 이겼다. 같은 파일 · 두 대답
- 파이썬도 **나중 줄이 이긴다**(셸과 같게). 그리고 겹친 열쇠를 **표준 오류로 말한다**
- 「셸이 이긴다」(§39 · thoth §40)는 그대로다. 겹침은 파일 안의 일이고 그 규칙과 다른 층이다

강제자 — `tests/test_lake.py::test_env_에_같은_열쇠가_둘이면_나중_줄이_이기고_말한다`

### 배운 것

**값이 틀린 것도 파일이 깨진 것도 아닐 때가 가장 어렵다.** 문법은 맞고 파일은 읽히고 도구는 돈다 —
다만 **조용히 틀린 값**을 쓴다. 401 은 권한을 가리켰고 권한은 멀쩡했다. 같은 설정을 두 로더가 읽는다면
**둘이 같은 답을 내는지**가 검사 항목이고, 다르면 그 차이는 언젠가 이렇게 나온다.

## §74. 의존성 그룹이 빠지면 그 그룹을 말한다

**2026-09-25**

### 결정

- FLORES+ 를 받으려고 `uv run --group data` 로 한 번 돌았더니, 그다음 AWS 기준선이
  `ModuleNotFoundError: boto3` 로 죽었다. **uv 는 부를 때 준 그룹으로 환경을 맞춘다** — 다른 그룹으로
  한 번 돌면 앞의 그룹이 빠진다. 고장이 아니라 그렇게 만들어진 도구다

- 리전 검사(§36) 바로 뒤다. **설정이 틀린 것은 설치로 덮지 않고, 설치가 빠진 것은 설정처럼 말하지 않는다**

강제자 — `tests/test_baselines.py::test_boto3_가_없으면_그룹을_말한다`

### 배운 것

**오늘 같은 모양의 고침이 다섯 번째다**(리전 §36 · `.env` 로더 §39 · ollama §51 · 동의 §71 ·
없는 셋 §72 · 그룹 §74). 전부 「바깥 것이 없을 때 도구가 다음 명령을 말하지 않는다」 였다.
새 바깥 의존을 붙일 때 **그 자리를 먼저 만든다** — 없을 때 무엇을 치면 되는지가 코드의 일부다.

## §75. 바깥 것이 없을 때 다음 명령을 말한다 — 규칙으로 적는다

**2026-09-25**

### 결정

- AWS 자격증명이 만료돼 botocore 가 40 줄을 뱉었다. **두 번째다**(2026-09-23 에도 같았다). 이제
  `aws_translate` 가 만료를 알아보고 말한다 : `친다 : aws login --profile fox`(프로필은 환경에서 읽는다)
- 만료가 아닌 거절은 **예외 이름을 그대로 보인다** — 모르는 고장을 아는 척 덮지 않는다

강제자 — `tests/test_baselines.py::test_자격증명이_만료되면_들어가는_법을_말한다`

### 이것을 규칙으로 적는다

오늘 하루에 **같은 모양의 고침이 일곱 번**이었다 :

| | 없던 것 | 종전 | 지금 |
|---|---|---|---|
| §36 | AWS 리전 | `NoRegionError` | `.env 에 AWS_REGION 을 적는다` |
| §39 | `.env` 로더 | 값이 조용히 비었다 | 패키지가 불러 오며 얹는다 |
| §51 | ollama 서버 | `URLError` 40 줄 | `ollama serve &` |
| §71 | 데이터셋 동의 | `GatedRepoError` | `Agree 를 누른다` |
| §72 | 평가셋 파일 | `FileNotFoundError` | `tools/fetch_flores.py` |
| §74 | 의존성 그룹 | `ModuleNotFoundError` | `uv run --group aws …` |
| §75 | AWS 세션 | botocore 40 줄 | `aws login --profile fox` |

**규칙** — 바깥 것(설정 · 서버 · 권한 · 파일 · 의존성 · 세션)에 기대는 코드를 새로 쓸 때, 그것이 없는
자리를 **같은 커밋에서** 만든다. 역추적은 도구가 제 일을 안 했다는 뜻이다. 사람이 다음에 칠 명령을
알려주는 것까지가 도구의 일이다(§51).

### 배운 것

**일곱 번이면 개별 사고가 아니다.** 하나씩 고칠 때마다 「다음엔 처음부터」 라고 적었고 일곱 번 다 나중에
고쳤다. 같은 고장이 반복되면 **고치는 것보다 그 고장이 날 수 있는 자리를 세는 일**이 먼저다 —
이 표가 그 목록이고, 다음에 바깥 것을 붙일 때 여기를 본다.
